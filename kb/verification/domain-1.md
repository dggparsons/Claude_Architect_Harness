## Corrections the harness must apply

1. **Refusals (row 2).** `stop_reason: "refusal"` arrives as a normal HTTP 200 response from Claude Fable 5.1, Fable 5, Opus 5.5, Opus 5, Sonnet 5.5 and Haiku 5.5, not only "Fable 5". Fable 5 is now a legacy model. Branch on `stop_reason` (not on `stop_details.category`, which can be `null`), log `stop_details`, and retry on a fallback model where appropriate.
2. **Forced tool use (row 6).** `tool_choice` is an object: `{"type": "any"}` or `{"type": "tool", "name": "..."}`. On Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1, `any` and `tool` return a 400 error; on those models use `auto` with strict tool use or structured outputs. On any model, `any` and `tool` are not supported with manual extended thinking (`thinking: {type: "enabled"}`) and result in an error; there, use `auto` or `none`.
3. **`allowedTools` is not a delegation gate (rows 8, 9).** In the Agent SDK, `allowedTools` / `allowed_tools` only auto-approves tools; it does not restrict which tools exist. `Agent` needs no approval, so it runs whether or not it is listed, and leaving it out does not send spawns to `canUseTool`. What actually removes delegation: `disallowedTools` naming `Agent`, a `tools` list that leaves it out (for example agent frontmatter `tools`), or, for a coordinator that is itself a subagent, the spawn-depth limit `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (it counts layers below the main conversation, so it never removes delegation from the main agent).
4. **"Coordinator will not delegate" (row 10).** Anthropic's documented fix is in the prompt: name the subagent in the prompt and write a clear `description`. With the `claude_code` preset on Opus 5, Claude Code adds a line telling Claude not to call `Agent` unless asked. Remove any decision rule that prefers adding `Task`/`Agent` to `allowedTools` over prompt changes, and any reviewer checklist item that says the same, or reword them as "check `Agent` is not denied or missing from a restrictive `tools` list".
5. **Agent-to-agent communication (rows 14, 17).** Hub-and-spoke is the default, but it is not absolute in current Claude Code. Subagents with the `SendMessage` tool can message other named agents in the session, and agent-team teammates (experimental) message each other directly. Keep "route through the coordinator" as a design choice, not as a platform fact.
6. **SDK hook availability (row 18).** `PostCompact` is TypeScript-only in the Agent SDK. The Python SDK does not have it.
7. **SubagentStop has a `decision` field (row 25).** SubagentStop uses Stop-style decision control: `{"decision": "block", "reason": "..."}` keeps the subagent running and sends `reason` as its next instruction. Exit code 2 with stderr does the same. `hookSpecificOutput.additionalContext` also keeps the subagent running, but it shows as hook feedback rather than a hook error. To let the subagent stop, exit 0 with neither `decision` nor `additionalContext`. It is not an absolute gate: "after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn"; the count resets when Claude calls a tool, and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` raises the cap (https://code.claude.com/docs/en/hooks, checked 2026-10-14).
8. **Hooks can rewrite tool results (row 26).** PostToolUse `hookSpecificOutput.updatedToolOutput` replaces what Claude sees for any tool, and the docs list no exception for `Agent`. It cannot undo side effects, and for built-in tools it is ignored if it does not match the tool's output shape. Drop the anti-pattern "any hook expected to rewrite a subagent's result". Instead, say that reshaping a subagent result in a PostToolUse hook is possible but hides the real output from Claude.
9. **Hooks and prompt injection (row 31).** Do not state that hooks "cannot be bypassed". The documented property is narrower: command hooks are deterministic, and a PreToolUse deny holds in every permission mode, including `bypassPermissions`. Known gaps: a typed `/skillname` skips PreToolUse (use UserPromptExpansion), a file changed through `Bash` skips an `Edit|Write` PostToolUse (use FileChanged), and `prompt`/`agent` hook types are model-judged. Test each hook.
10. **PostToolUse "block" does not stop the loop (row 38).** `decision: "block"` or exit 2 only adds feedback beside the result, and Claude continues. To halt, return `"continue": false`. Either way the side effect has already happened.

## Caveats on confirmed rows (worth carrying into the harness)

- `permissionDecision: "defer"` is honoured only in non-interactive `-p` runs. Interactive sessions log a warning and ignore it (row 19).
- The SDK `system:init` tools list still names the delegation tool `Task`, while `tool_use` blocks say `Agent`, so detection code should match both (row 7).
- Frontmatter `hooks` are ignored for plugin subagents. Project-subagent frontmatter hooks need workspace trust, and a `-p` session does not count as trust (row 27).
- `--continue` skips `-p`, Agent SDK and `/loop` sessions unless it is itself run with `-p` (row 34).
- In streaming, `stop_reason` is null in the `message_start` event (row 1).
- `model_context_window_exceeded` needs the beta header `model-context-window-exceeded-2025-08-26` on models older than Sonnet 4.5 (row 3).
- In a tool-result user message, the `tool_result` blocks must come first, before any text (row 5).
