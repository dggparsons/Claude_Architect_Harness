## Corrections the harness must apply

1. **Tool descriptions (#3):** Anthropic calls detailed descriptions "by far the most important factor in tool performance", with at least 3–4 sentences each. It does not say they matter more than names; it also recommends service-prefixed names (`github_list_prs`).
2. **Tool count (#4):** Anthropic's documented threshold is that selection "degrades once you exceed 30–50 available tools". Tool search is recommended from 10 or more tools. Keep "4–5 per agent" only as a labelled house heuristic, not an Anthropic figure.
3. **`tool_choice` modes (#5):** there are four modes: `auto` (default when tools are given), `any`, `tool`, `none` (default when no tools are given).
4. **`tool_choice` shape (#6):** always an object (`{"type": "any"}`), never a bare string (`"any"`).
5. **Forced tool use (#7):** `any` and `tool` return HTTP 400 on Claude Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1. On those models, use `auto` plus `strict: true` for schema-valid tool inputs, or structured outputs for a fixed JSON reply. With manual extended thinking (`thinking: {type: "enabled"}`), on any model, `any` and `tool` are not supported and result in an error (the docs give no status code); use `auto` or `none`. Forcing a tool also skips thinking. Pick the mode in code per model; never hard-code forced `tool_choice`.
6. **Streamable HTTP (#13):** each message is an HTTP POST to one MCP endpoint, and the reply is either a JSON object or a request-scoped SSE stream, so SSE is optional. The old standalone SSE transport is deprecated in Claude Code.
7. **Client to server (#14):** each MCP client talks to exactly one server (1:1). One host runs many clients. The glossary's "one or more servers" is wrong.
8. **`CallToolResult` (#18):** in revision 2026-07-28 it has `content` (required), `structuredContent?` (any JSON value), `isError?` (default false), the inherited `resultType` (required from servers on this revision; `"complete"` for a final result, `"input_required"` when the server needs input; a client "MUST treat the absent field as `"complete"`" from an older server) and `_meta?`. Schema checks on tool results must allow `resultType` and `_meta`.
9. **Spec revision (#20):** cite `modelcontextprotocol.io/specification/2026-07-28/...` (or `/latest/`), not 2025-06-18.
10. **Error layers (#21):** argument and input-validation failures (wrong format, out of range) are tool execution errors. Return them as results with `isError: true` so the model can self-correct. Only unknown tools, requests that fail the `CallToolRequest` schema, and server errors are JSON-RPC protocol errors (`-32602` for an unknown tool).
11. **Example config (#26):** the GitHub URL `https://api.githubcopilot.com/mcp/` is confirmed. The Atlassian URL and the `server-filesystem` npx line are not in Anthropic's docs. Mark them unverified, or drop them from harness templates.
12. **Credentials (#27):** for remote (`http`) servers, put credentials in `headers` (for example `"Authorization": "Bearer ${GITHUB_MCP_PAT}"`). `env` only sets environment variables for a stdio server's process.
13. **Unset variables (#29), detail to add:** for a documented set of credential names (Claude Code's own such as `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN`, cloud-provider ones such as `AWS_BEARER_TOKEN_BEDROCK`, and others such as `NPM_TOKEN` and `HTTPS_PROXY`), a remote server's `url` and `headers` expand them to empty with no warning, and `:-default` is ignored. Use your own variable names. An unset non-covered variable is passed through as the literal `${VAR}` text.
14. **MCP tool loading (#31):** tool search is on by default. MCP tools are deferred, and only tool names and server instructions load at session start; Claude finds the rest through `ToolSearch`. Servers connect in the background. To force upfront loading, use `alwaysLoad: true` per server in your configuration, or `ENABLE_TOOL_SEARCH=false`; a server author can set `_meta["anthropic/alwaysLoad"]: true` on one tool, and the user's server-level setting can override it. Tool search is off, and tools load upfront, with a non-first-party `ANTHROPIC_BASE_URL`, on models earlier than Opus 4 and Sonnet 4 (on Google Cloud's Agent Platform, earlier than Opus 4.5, Sonnet 4.5 and Haiku 4.5), and on Microsoft Foundry deployments hosted on Azure. By default (Claude Code v2.1.296 or later, checked 2026-10-14), server instructions and upfront-loaded tool descriptions are cut at 4,096 characters and deferred tool descriptions at 16,384 (before v2.1.296 the shorter limit was 2,048); tool search matches only within the shorter limit, and `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` replaces both limits. Put the key words first.
15. **Official remote servers (#34):** only GitHub's official remote server is confirmed in Anthropic's docs. The Atlassian claim is unverified.
16. **Built-in tools (#36):** Claude Code has far more than six built-in tools (the tools reference lists 46 rows, one marked removed), including `Agent`, `Skill`, `WebFetch`, `WebSearch`, `NotebookEdit`, `LSP`, `PowerShell`, `ToolSearch`, `ListMcpResourcesTool` and `ReadMcpResourceTool`.
17. **Grep and Glob (#37):** they are default tools only on Windows. On macOS, Linux and WSL, Claude searches with `find` and `grep` through Bash, which run embedded `bfs` and `ugrep`. Do not flag Bash `find`/`grep` as an anti-pattern on those platforms. Grep and Glob come back if you name them in `--tools`/`--allowedTools` or remove Bash. Hooks and permission rules see those searches as `Bash` calls.
18. **Edit error text (#38):** the uniqueness rule is confirmed, but "old_string matches 3 locations" is not documented error text. Do not match on that string in tests or hooks.
