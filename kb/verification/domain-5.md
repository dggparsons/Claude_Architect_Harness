## Corrections the harness must apply

1. **Context-window sizes (claim 16).** Every current model is 1M tokens with 128K max output: Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5. The 1M window is the default and needs no beta header. Only older models are 200K, among them Haiku 4.5 and Sonnet 4.5 (deprecated). Replace "200K (Haiku 4.5) to 1M (Sonnet 5, Opus 5, Fable 5)" with this, dated 2026-10-14. The window covers input plus output, and cached tokens still count toward it. In Claude Code, Fable 5.1, Fable 5, Sonnet 5 and later, Haiku 5.5, and Opus 4.7 and later run at 1M by default. Opus 4.6 and Sonnet 4.6 reach 1M only through the `[1m]` variant, and access depends on the plan.
2. **System role (claim 8).** A `"role": "system"` message inside `messages` is now valid, with no beta header, on Fable 5.1, Mythos 5.1, Fable 5, Mythos 5, Opus 5.5, Opus 4.8, Opus 5, Sonnet 5.5 and Haiku 5.5. It must immediately follow a user turn (including one carrying tool results) and must either end `messages` or be followed by an assistant turn; it cannot be the first entry, and one followed directly by another user message returns 400. It is not available on Sonnet 5. Remove "attempt to use a `"system"` role inside `messages`" as a blanket anti-pattern. The rule becomes: instructions that apply from the start go in top-level `system`; a mid-conversation system message is valid on supported models and does not invalidate the cached prefix before it.
3. **Context full (claim 5).** Replace "conversation history is lost" with the following. Claude Code auto-compacts near the limit. On native-1M models the default trigger is about 967K tokens; it can be set with `/autocompact`. Compaction replaces the conversation with a structured summary in which verbatim tool output and intermediate reasoning are lost. CLAUDE.md, auto memory, up to five of the files Claude read or edited (most recently modified first; a file over 5,000 tokens returns as a path only) and invoked skill bodies are reloaded. Manual `/compact` and auto-compaction work the same way ("The automatic pass works the same way as the `/compact` step"); a focused `/compact` keeps what you choose. Nested CLAUDE.md files and path-scoped rules are summarised away until their trigger file is touched again. On the raw API, an input that exceeds the window returns 400 "prompt is too long". The advice to keep findings in files still stands.
4. **Retry-After (claim 17).** Honour `retry-after` when it is present, but do not assume every 429 carries it. A Messages API 429 with `error.details.error_code == "enforced_spend_limit_reached"` (the monthly spend cap) has no `retry-after` and keeps failing until access resumes, so stop and report rather than retry. The official SDK already retries connection errors, 429s and 5xx errors twice with backoff by default (`max_retries` in Python; `maxRetries` in TypeScript). Do not stack a second unbounded retry loop on top of it.
5. **Usage fields (claim 15).** With prompt caching, `usage.input_tokens` counts only tokens after the last cache breakpoint. Total input = `cache_read_input_tokens + cache_creation_input_tokens + input_tokens`. Cost and context accounting must sum all three.
6. **Cache layout (claim 26).** The prefix order is `tools` → `system` → `messages`, so tool definitions go in `tools`, not `system`, and any change to them invalidates the whole cache. Either place up to 4 explicit `cache_control` breakpoints, or use top-level automatic caching (`"cache_control": {"type": "ephemeral"}` on the request body), which uses one of the 4 slots. Prompts below the model minimum are silently not cached. Minimums on the Claude API, Claude Platform on AWS, Google Cloud and Microsoft Foundry: 512 tokens for Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5, Sonnet 5.5, Fable 5, Mythos 5 and Haiku 5.5; 1,024 for Opus 4.8, Sonnet 5, Sonnet 4.6 and Sonnet 4.5 (deprecated); 2,048 for Mythos Preview and Opus 4.7; 4,096 for Opus 4.6, Opus 4.5 and Haiku 4.5. When mixing TTLs, 1-hour entries must come before 5-minute entries.
7. **"Lost in the middle" (claim 19).** Do not cite Anthropic for "beginning and end are processed reliably". The documented rule is to put long documents at the top, above the query, instructions and examples, and to put the query at the end (up to 30% better in Anthropic's tests). Update the source URL to `https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#long-context-prompting`; the old `long-context-tips` path redirects there.
8. **Citation labels (claims 22–24).**
   - Use `https://platform.claude.com/docs/en/about-claude/use-case-guides/customer-support-chat`, without the doubled `docs/en/docs`. The page is "Customer support agent". It gives no escalation rules, only an "escalation efficiency" metric (target 95% or higher).
   - Relabel `agent-sdk/structured-outputs` as "Agent SDK: Get structured output from agents". It covers JSON Schema output validation, not extraction or calibration.
   - Relabel `build-with-claude/citations` as "Citations (API feature)". The native Citations API is GA and supported on all active models. It is a candidate carrier for claim–source provenance in Claude apps; the guide does not discuss it.
9. **Exam-scope claims (20, 21).** These are unverified. Keep them marked as unverified until they are checked against the official exam guide, which is outside the permitted sources.

**Advisories on CONFIRMED items (current facts the harness should carry)**
- Claim 7: the API is stateless, but server-side compaction exists in beta in two kinds, each with its own header. On demand: header `compact-2026-09-04` and the top-level `compaction` parameter; send the returned block first, in place of the turns it summarises. At a token threshold: header `compact-2026-01-12` and `compact_20260112` in `context_management.edits`; append the response as usual and the API drops what came before the block. Context editing (clearing tool results and thinking blocks) also exists. "Send full history" still holds, but the history may contain a compaction block.
- Claim 14: `claude-sonnet-5` is valid but legacy (retirement not sooner than June 30, 2027). Use `claude-sonnet-5-5` in new examples. Sonnet 5's minimum cacheable prompt is 1,024 tokens.
- Claim 10/12: cache reads cost 0.1× base input (0.05× on Opus 5.5 and Sonnet 5.5; 0.025× on Fable 5.1 and Mythos 5.1). Cache writes cost 1.25× for the 5-minute TTL and 2× for the 1-hour TTL. In Claude Code the main conversation gets a one-hour cache by default on a subscription within plan usage; everything else, subagents included, gets five minutes (apart from a few server-controlled helper requests), and so does usage drawn from usage credits, an API key or a cloud provider. `promptCacheTtl` and `subagentPromptCacheTtl` change it (https://code.claude.com/docs/en/prompt-caching: "Subagents fall outside the main-conversation TTL bucket, so they get five minutes even on a subscription"; costs page: "drops to five minutes once you're drawing on usage credits").
- Claim 2: `/compact` is itself a large request; use `/clear` when continuity is not needed. Focus instructions can also go under a `# Compact instructions` heading in the project CLAUDE.md (costs page).
- Claim 4: PostToolUse runs after the tool has already executed, and telemetry records the original output. For built-in tools the replacement must match the tool's output schema or it is ignored. To prevent or reshape a call, use PreToolUse `updatedInput`; the costs page shows exactly this, filtering test output.
- Claim 18: batch requests not processed within 24 hours expire and are not billed. Results stay available for 29 days. Limits: 100,000 requests or 256 MB per batch. Prompt-caching discounts stack with the batch discount.
